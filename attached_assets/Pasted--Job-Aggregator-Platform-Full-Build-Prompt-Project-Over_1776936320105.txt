# Job Aggregator Platform — Full Build Prompt

## Project Overview

Build a full-stack job aggregator platform that scrapes live job listings from Google Jobs, Indeed, LinkedIn, and Naukri using Playwright. The backend is a secure Express.js REST API following MVC architecture. The frontend is React + Vite + Tailwind + shadcn/ui — minimal, clean, functional.

**No auth. No AI (yet). No Redis. No extra validations beyond what is needed for secure API serving.**
Quality priority: scraping reliability > everything else.

---

## Stack

| Layer | Technology |
|---|---|
| Runtime | Node.js 20+ |
| Scraper | Playwright (Chromium) |
| Web framework | Express.js |
| Cache | In-memory (node-cache) |
| Architecture | MVC (Model–View–Controller) |
| Frontend | React 18 + Vite + Tailwind CSS v3 + shadcn/ui |

---

### 2. Security Middlewares

Apply globally in `app.js` in this order:

```js
import helmet from 'helmet'
import cors from 'cors'
import rateLimit from 'express-rate-limit'
import { sanitize } from './middlewares/sanitize.js'

app.use(helmet())                          // sets secure HTTP headers
app.use(cors({ origin: config.allowedOrigins }))
app.use(express.json({ limit: '10kb' }))   // body size cap
app.use(sanitize)                          // strips unknown query params, trims strings
app.use('/api', apiLimiter)                // 60 req/min per IP
```

**`sanitize.js`**: whitelist only known query params for `/api/jobs` — `skills`, `experience`, `domain`, `location`, `remote`, `page`, `limit`, `source`. Strip everything else. Trim all string values. Convert `page` and `limit` to integers, clamp `limit` max to 20.

**`rateLimiter.js`**: express-rate-limit, 60 requests per 15 minutes per IP, JSON error response `{ error: "Too many requests" }`.

**`errorHandler.js`**: global Express error handler, returns `{ error: message, code }`, never leaks stack traces in production.

**`logger.js`**: morgan for HTTP logs in dev, minimal in prod. Also export a custom `log(level, msg, meta)` using console with timestamps.

### 3. Job Model (`server/src/models/jobModel.js`)

Normalised plain object schema. All scrapers must return this shape:

```js
{
  id: string,           // hash of (title + company + url)
  title: string,
  company: string,
  location: string,
  remote: boolean,
  salary: string | null,
  experience: string | null,
  skills: string[],
  domain: string | null,
  postedAt: string | null,   // ISO date string or relative ("2 days ago")
  applyUrl: string,
  source: 'google' | 'indeed' | 'linkedin' | 'naukri',
  scrapedAt: string,    // ISO timestamp
}
```

Export a `normaliseJob(raw, source)` function that takes a raw scraper object and returns a validated, filled-in job model. Fill missing fields with `null`, not `undefined`. Generate `id` using a SHA-256 hash of `title + company + applyUrl`.

### 4. Scrapers

Each scraper exports an async function:
```js
async function scrape(params, proxyConfig) -> Job[]
```

**params shape:**
```js
{
  skills: string,       // e.g. "react node.js"
  experience: string,   // e.g. "3 years"
  domain: string,       // e.g. "software"
  location: string,     // e.g. "bangalore"
  remote: boolean,
  page: number,
  limit: number,
}
```

**Playwright config (apply to ALL scrapers):**

```js
const browser = await chromium.launch({
  headless: true,
  proxy: {
    server: `http://${proxyConfig.host}:${proxyConfig.port}`,
    username: proxyConfig.user,
    password: proxyConfig.pass,
  },
  args: [
    '--no-sandbox',
    '--disable-setuid-sandbox',
    '--disable-blink-features=AutomationControlled',
    '--disable-dev-shm-usage',
  ],
})

const context = await browser.newContext({
  userAgent: 'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0.0.0 Safari/537.36',
  viewport: { width: 1366, height: 768 },
  locale: 'en-US',
  timezoneId: 'Asia/Kolkata',
  extraHTTPHeaders: {
    'Accept-Language': 'en-US,en;q=0.9',
  },
})

// Block images, fonts, media to speed up scraping
await context.route('**/*.{png,jpg,jpeg,gif,svg,woff,woff2,mp4,webm}', r => r.abort())
```

Always call `browser.close()` in a `finally` block.

Add random delay between actions: `await page.waitForTimeout(Math.random() * 1500 + 500)`.

**googleJobsScraper.js:**
- Navigate to `https://www.google.com/search?q={query}+jobs+in+{location}&ibp=htl;jobs`
- Build query from `skills + domain + experience` params
- Wait for `.iFjolb` or `[jsname='bVMuJe']` job card container
- Extract each job card: title (`.BjJfJf`), company (`.vNEEBe`), location (`.Qk80Jf`), posted (`.SuWscb`), apply link (`.pMhGee a`)
- Handle Google's paginated job drawer — scroll the job list container, not the page
- Return up to `limit` jobs per call

**indeedScraper.js:**
- URL: `https://in.indeed.com/jobs?q={skills}+{domain}&l={location}&start={page*10}`
- Extract from `.job_seen_beacon`: title `.jobTitle`, company `.companyName`, location `.companyLocation`, salary `.salary-snippet`, posted `.date`
- Extract apply link from job detail click or `data-jk` attribute → `https://in.indeed.com/viewjob?jk={jk}`

**linkedinScraper.js:**
- URL: `https://www.linkedin.com/jobs/search/?keywords={query}&location={location}&start={page*25}`
- No login required for public listings
- Extract from `.job-search-card`: title `.base-search-card__title`, company `.base-search-card__subtitle`, location `.job-search-card__location`, link `.base-card__full-link`
- Handle lazy loading: scroll page slowly before extraction

**naukriScraper.js:**
- URL: `https://www.naukri.com/{skills}-jobs-in-{location}?experience={experience}`
- Extract from `.jobTuple`: title `.title`, company `.companyInfo .subTitle`, location `.locWdth`, experience `.expwdth`, salary `.salaryText`, link `a.title[href]`

**Error handling in scrapers:**
- Catch navigation timeouts → return `[]` with a warning log, do NOT throw
- If selector not found → return `[]`, log warning
- Never let one scraper failure crash the whole request

### 5. Scraper Service (`scraperService.js`)

Orchestrates all scrapers in parallel:

```js
export async function searchJobs(params) {
  const sources = params.source
    ? [params.source]
    : ['google', 'indeed', 'linkedin', 'naukri']

  const results = await Promise.allSettled(
    sources.map(src => runScraper(src, params))
  )

  const jobs = results
    .filter(r => r.status === 'fulfilled')
    .flatMap(r => r.value)

  // Deduplicate by id
  const seen = new Set()
  return jobs.filter(j => {
    if (seen.has(j.id)) return false
    seen.add(j.id)
    return true
  })
}
```

### 6. Cache Service (`cacheService.js`)

Use `node-cache` package:

```js
import NodeCache from 'node-cache'
const cache = new NodeCache({ stdTTL: config.cacheTtl, checkperiod: 120 })

export function getCacheKey(params) {
  return JSON.stringify({
    skills: params.skills,
    experience: params.experience,
    domain: params.domain,
    location: params.location,
    remote: params.remote,
    page: params.page,
    source: params.source,
  })
}

export { cache }
```

### 7. Controller (`jobsController.js`)

```js
export async function getJobs(req, res, next) {
  try {
    const params = buildParams(req.query)   // sanitised by middleware
    const cacheKey = getCacheKey(params)

    const cached = cache.get(cacheKey)
    if (cached) return res.json({ ...cached, fromCache: true })

    const allJobs = await searchJobs(params)

    // Pagination
    const page = params.page
    const limit = params.limit
    const start = (page - 1) * limit
    const paginatedJobs = allJobs.slice(start, start + limit)

    const response = {
      jobs: paginatedJobs,
      meta: {
        page,
        limit,
        total: allJobs.length,
        totalPages: Math.ceil(allJobs.length / limit),
        hasNext: start + limit < allJobs.length,
        hasPrev: page > 1,
      },
      fromCache: false,
    }

    cache.set(cacheKey, response)
    res.json(response)
  } catch (err) {
    next(err)
  }
}
```

### `useJobs` hook

```js
export function useJobs(params) {
  return useQuery({
    queryKey: ['jobs', params],
    queryFn: () => api.get('/jobs', { params }).then(r => r.data),
    staleTime: 1000 * 60 * 5,
    enabled: !!(params.skills || params.domain || params.location),
    keepPreviousData: true,
  })
}
```

## Key Implementation Notes

1. **Playwright install**: `npx playwright install chromium --with-deps` — add this to README setup.

2. **Proxy fallback**: If `PROXY_USER` is empty in `.env`, launch browser without proxy (for local dev/testing without Brightdata).

3. **Scraping is slow** (5–15s per source). Frontend must show loading skeletons and a message like "Searching across job boards…"

4. **Cache TTL**: Default 5 minutes. Same query within TTL returns instantly from cache.

5. **Deduplication**: Two jobs with same title + company from different sources → keep both (different `source` field) unless `applyUrl` is identical.

6. **robots.txt**: This platform is for personal/research use. Respect rate limits via Playwright delays. Use residential proxies to avoid blocks.

7. **Google Jobs special**: Google's job results are inside an iframe-like component. Use `page.waitForSelector('[jscontroller]')` then extract from the jobs panel, not the main SERP.

8. **LinkedIn**: Scroll the job list container (`window.scrollBy`) 3–4 times with `waitForTimeout` between each scroll to trigger lazy loading before extracting.

9. **Naukri**: May require accepting cookie banners — add `page.click` for common cookie accept buttons before scraping.

10. **package.json scripts (server)**:
```json
{
  "start": "node src/app.js",
  "dev": "nodemon src/app.js",
  "install:browsers": "npx playwright install chromium --with-deps"
}
```

## What NOT to build (scope limits for v1)

- No user auth / JWT
- No database (no PostgreSQL, no MongoDB)
- No AI processing / enrichment
- No Redis / queue
- No email alerts / saved jobs
- No admin panel
- No Docker (yet)
- No rate limiting per user (only per IP)
- No input validation beyond sanitization middleware

These are v2+ features. Build the above to production quality first.
